# 原生客户端与窗口控制

客户端使用 MaaEnd 同款 MXU 桌面界面，以 ProjectInterface 配置任务、队伍选项、
游戏语言和控制器。新增中文界面词条；游戏识别资源仍为英语和日语。
`assets/misc/Don-Quixote.png` 是本项目生成的小唐图标，通过 PI 的 `icon`
加载到窗口、标题栏、关于页和托盘，不修改 MXU 可执行文件。

## 参考实际实现

本次核对 MaaEnd 提交 `850e5fa026cd5daebe74ef73ddb265cdc7b55d21` 的
[PI 控制配置](https://github.com/MaaEnd/MaaEnd/blob/850e5fa026cd5daebe74ef73ddb265cdc7b55d21/assets/interface.json)：

| 本项目控制器 | Maa 截图 | Maa 鼠标 | Maa 键盘 |
| --- | --- | --- | --- |
| windows-window（默认） | Background | SendMessageWithCursorPos | PostMessage |
| windows-background | Background | SendMessageWithWindowPos | PostMessage |
| windows（保留旧名称） | ScreenDC | Seize | Seize |

三种组合与 MaaEnd 相同，保留已有 `windows` 配置名称；CLI 从同一 PI 文件
读取控制参数，不再硬编码前台方式。GUI 已由 MXU 读取这些设置。
Lix `431b432e22f0b0da08b95d7c478fa213be20b3e8` 的
`lalc_backend/input/input_handler.py` 默认后台状态，鼠标/键盘使用窗口消息；
`update_to.bat` 也包含标准 RunAs 启动。没有引入它的控制器或 BlockInput。

MaaEnd 三种 Win32 控制器均设置 `permission_required: true`。
MXU 在任务启动时处理正常的 Windows 管理员启动，不需要另外通过聊天选择题批准。
项目不会自动重试先前已取消的 UAC，也不绕过 Windows 的输入隔离。

## 无人值守启动：模拟器、游戏、任务

从开机到进游戏分三段，每段各管一件事，做法对照 MaaEnd：

| 段 | 谁来做 | 说明 |
| --- | --- | --- |
| 启动 MaaLimbus 并自动开始 | MXU 自带设置 | 「开机自启动」会建一个登录时运行的计划任务；「启动后自动执行」指定要跑的配置。这两项是 MXU 的设置，不在本项目的任务里。 |
| 启动模拟器 | 预任务 `launch_emulator` | MXU 在连接 ADB 设备**之前**运行它。它启动你填的模拟器程序，然后等模拟器的 ADB 地址能连上；模拟器已经在运行就什么都不做。 |
| 启动游戏 | 任务「打开游戏」 | 连接之后由 MaaFramework 启动游戏并独立确认前台。游戏已经在前台时不重复启动；启动后一直没到前台，就关闭游戏再启动一次，只修一次。 |

预任务的四个设置：模拟器程序的完整路径、启动参数（用来选实例）、ADB 地址（要和 MXU 连接的地址一致，只接受本机地址）、最长等待秒数（10–600，默认 180）。程序路径留空表示模拟器由你自己打开，这时地址连不上会直接说明原因，不会去猜模拟器装在哪里。

MXU 在预任务之后不会再等设备出现，所以等待是预任务自己做的：每秒试一次连接，连上后再等 5 秒。端口能连上之后它继续等安卓开机完成（`adb shell getprop sys.boot_completed` 为 1）才返回，用的 adb 是记住的那一个，或者你填的程序旁边的 `adb.exe`；两处都没有 adb 时只等端口，和以前一样。2026-11-26 之前它只等端口：用户在桌面窗口点开始，预任务 8 秒返回，MXU 立刻连设备、4 秒内连了三次都失败，任务列表没有开始——当天实测端口通了之后还要 4～14 秒安卓才开机完成。等待总时长仍受「最长等待秒数」限制，超时以 `emulator_android_not_booted` 失败。之后的「打开游戏」任务会等到游戏真正在前台。预任务的结论用退出码表示（0 通过，1 未通过），并打印原因，例如 `emulator_program_not_configured`、`emulator_not_reachable`。MXU v2.7.1 对预任务失败只记一条警告并继续，接下来连接设备会失败并停下。

可以不经过 MXU 单独试预任务：

```powershell
python agent/main.py --pretask launch_emulator '{"launch_emulator": {"program": "", "arguments": "", "address": "127.0.0.1:16384", "wait_seconds": "60"}}'
```

打包后的应用里，同一个预任务由 `agent/MaaLimbusAgent.exe --pretask launch_emulator` 执行。

### 记住模拟器、关闭游戏、关闭模拟器

2026-11-26 新增三个普通任务（只在 Android 控制器下出现），和「启动模拟器」里的一个选择：

| 任务 | 做什么 | 边界 |
| --- | --- | --- |
| 检测模拟器并记住 | 连上模拟器时运行一次：控制器用的 `adb.exe` 旁边如果有 `MuMuManager.exe`，就用它的只读命令（`info -v all`、`setting -v N -a`）找出 ADB 端口等于当前地址的那个实例，把启动方式、关闭方式和地址记到数据目录的 `user-emulators.json` | 不搜索磁盘、不读注册表、不改模拟器任何设置。设置里只留分辨率、DPI、帧率四项，其余（含设备标识）不保存也不写日志。旁边没有管理程序的 adb 只记地址，不声称能启动它 |
| 关闭游戏 | 用控制器停止 Limbus Company，再读一次前台确认它不在了 | 正在进行的战斗不会保存，所以放在任务列表最后 |
| 关闭模拟器 | 用记住的管理程序关闭**当前连接地址对应的那一个实例**，等它不再应答 | 没记住过这台就拒绝并说明；不碰别的实例，也不结束任何进程 |

「启动模拟器」预任务现在先问「用哪台模拟器」：「使用已记住的模拟器」读上面记下的那一台，什么都不用填；「手动填写」（默认）沿用原来的四个设置，所以以前保存的配置行为不变。没有记住过就选了「已记住」，预任务以 `emulator_not_remembered` 失败并说明原因，不会去猜。MXU 把单选项的所选情形名和它下面嵌套的选项一起传给预任务，这是照 MXU 2.7.1 自己的序列化代码核对的。

**不重复做的**：关机、重启、睡眠、息屏和退出本程序，MXU 自带，在「添加任务 → 特殊任务」里的「⚡ 电脑操作」和「⛔ 结束进程」（可选结束自身）。

**检测时顺带报告、但不修改的**：程序的页面是在 1280×720、DPI 240、最高 60 帧下测的。检测任务读出这台模拟器的这四个值，不一样就在结果里提醒。MuMu 的管理程序可以改这些值，但那是动用户的模拟器设置，目前没有做，要做也只会是一个默认关闭的选项。游戏内的画面设置同理，还没有看过那一页。

**实机结果（2026-11-26，安装版，MuMu 6.8.17 第 1 个实例）**：四个任务各跑通一次——检测并记住（记录写入、界面显示完成）、打开游戏、关闭游戏（之后前台为空）、关闭模拟器（实例停止、地址不再应答）；用记住的记录启动两次，只启动了第 1 个实例，第 0 个没有被碰。加了等待开机之后的预任务用时 18 秒，返回时 `sys.boot_completed` 为 1。用户在桌面窗口的那次开始也证实了 MXU 传给预任务的选项格式（`{"launch_emulator_source":"manual","launch_emulator":{…}}`）。**一次没有重现的崩溃**：有一轮列表以「关闭模拟器」结尾，结束后我在外面把模拟器重新启动了，MXU 随即自动重连设备，7 秒后在停止 Agent 时 `MaaLimbus.exe`（MXU 2.7.1）崩溃退出（0xc0000409，ucrtbase.dll）。单独再跑一次「关闭模拟器」、不去重启模拟器，程序没有崩。只有这一次观察，原因没有查明；MXU 是未修改的上游程序。**没验证的**：加了等待开机的预任务是用源码直接跑的，打包后的安装版还没有重建；完整的「预任务 → 连接 → 任务列表」在桌面窗口里还没有成功走完一次。

## 实机证据边界

窗口消息是否被 Limbus 接受，必须以操作后的实际页面变化证明；不能由枚举解析
或后台方式的名称推断。最新只读检查记录在 `build/control-reference-preflight.json`：
游戏 PID 40196 / HIGH 12288，检查进程 MEDIUM 8192；游戏最小化且客户区 0×0。
FramePool/Background 原生截图失败，日志同时保留访问拒绝与零尺寸错误；
不单独把截图失败全部归因于权限。未发送游戏输入，未验证实机导航/战斗。

只读检查使用 Null 鼠标与键盘、单控制器锁和有限等待：

```powershell
python tools/probe_win32.py --binary <Maa目录> --capture Background
```
